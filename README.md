### ❓ Como executar, usar e testar o produto

----

☑️ **Definition of Ready (DoR)** 

-   Não ter dependência de outra tarefa;
  
-   Todos os pré requisitos da tarefa precisam estar prontos;
 
-   User Story detalhada e bem compreendida pela equipe com critérios de aceitação;
 
-   Distribuir cada tarefa ao seu respectivo desenvolvedor;

-   Definir 2 QAs (Quality Assurance) por tarefa;

---- 

☑️ **Definition of Done (DoD)**

-   O commit precisa ser aprovado pelos mesmos QAs que aprovaram as tarefas (todo Pull Request precisa ter dois aprovadores);

-   Os commits precisam seguir o padrão estabelecido pela equipe;

-   Testado pelo desenvolvedor;
  
-   Documentação do GitHub atualizada, com um responsável por sprint;
